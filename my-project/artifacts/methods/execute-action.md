# Назначение

Метод исполняет подтверждённое клиентом действие через Core Banking API. Доступно только для действий в состоянии PENDING_CONFIRMATION.

# Алгоритм работы

1. Принять идентификатор действия.
2. Проверить существование действия с указанным action_id.
3. Проверить, что действие находится в состоянии PENDING_CONFIRMATION (подтверждено клиентом).
4. Вызвать Core Banking API для исполнения операции (перевод, платёж и т.д.).
5. Если исполнение успешно:
   5.1. Изменить статус на EXECUTED.
   5.2. Записать результат исполнения.
6. Если исполнение завершилось ошибкой:
   6.1. Изменить статус на FAILED.
   6.2. Записать код ошибки.
7. Записать событие в аудит-лог с указанием исходной системы (core-banking-sim).

# Входные атрибуты

| Атрибут | Где передается | Тип данных | Описание |
|---------|---------------|------------|----------|
| action_id | path | string | Идентификатор действия |

# Выходные атрибуты

| Атрибут | Тип данных | Описание |
|---------|------------|----------|
| action_id | string | Идентификатор действия |
| status | string | Новый статус (executed или failed) |
| message | string | Сообщение о результате исполнения |
| result | object | Результат исполнения (зависит от типа действия) |

# Пример запроса

(пустое тело запроса)

```http
POST /actions/act-000001/execute
```

# Пример ответа

Успешное исполнение:

```json
{
  "action_id": "act-000001",
  "status": "executed",
  "message": "Перевод выполнен успешно.",
  "result": {
    "status": "executed",
    "executed_at": "2024-06-15T10:30:00Z"
  }
}
```

Ошибка исполнения:

```json
{
  "action_id": "act-000001",
  "status": "failed",
  "message": "Ошибка выполнения перевода.",
  "result": null
}
```

# Коды ответа

- `200` — действие исполнено
- `400` — действие не подтверждено или уже исполнено
- `401` — не авторизован
- `404` — действие не найдено
- `500` — ошибка при исполнении (Core Banking)
