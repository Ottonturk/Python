# Назначение

Метод позволяет клиенту подтвердить или отклонить подготовленное действие (например, перевод) через 2FA / push-уведомление. Без подтверждения клиента действие не исполняется банковской системой.

# Алгоритм работы

1. Принять идентификатор действия и флаг подтверждения (confirmed: true/false).
2. Проверить существование действия с указанным action_id.
3. Проверить, что действие находится в состоянии PENDING (ожидает подтверждения).
4. Если confirmed = true:
   4.1. Изменить статус действия на PENDING_CONFIRMATION.
   4.2. Записать время подтверждения.
   4.3. Вернуть клиенту сообщение о готовности к исполнению.
5. Если confirmed = false:
   5.1. Изменить статус действия на CANCELLED.
   5.2. Вернуть клиенту сообщение об отмене.
6. Записать событие в аудит-лог.

# Входные атрибуты

| Атрибут | Где передается | Тип данных | Описание |
|---------|---------------|------------|----------|
| action_id | path | string | Идентификатор действия |
| confirmed | body | boolean | true — подтвердить, false — отклонить действие |

# Выходные атрибуты

| Атрибут | Тип данных | Описание |
|---------|------------|----------|
| action_id | string | Идентификатор действия |
| status | string | Новый статус (pending_confirmation или cancelled) |
| message | string | Сообщение клиенту о результате |

# Пример запроса

```json
{
  "confirmed": true
}
```

# Пример ответа

Успешное подтверждение:

```json
{
  "action_id": "act-000001",
  "status": "pending_confirmation",
  "message": "Действие подтверждено. Ожидается исполнение через Core Banking API."
}
```

Отклонение действия:

```json
{
  "action_id": "act-000001",
  "status": "cancelled",
  "message": "Действие отменено по запросу клиента."
}
```

# Коды ответа

- `200` — действие подтверждено или отклонено
- `400` — действие не в состоянии ожидания (уже подтверждено, исполнено или отменено)
- `401` — не авторизован
- `404` — действие не найдено
