# Назначение

Метод принимает текстовое сообщение клиента, определяет намерение (сценарий A, B, C или эскалация), формирует ответ с использованием базы знаний банка (RAG) и, при необходимости, создаёт действие требующее подтверждения клиентом. Возвращает ответ клиенту с источниками информации и уровнями уверенности.

# Алгоритм работы

1. Принять сообщение клиента с идентификатором клиента и текстом запроса.
2. Проверить аутентификацию клиента (JWT токен).
3. Передать запрос в LLM для определения намерения и извлечения сущностей.
4. Если намерение — объяснение комиссии (сценарий A):
   4.1. Выполнить поиск в RAG базе знаний с фильтром по дате (актуальные условия на дату запроса).
   4.2. Передать найденные чанки в LLM для формирования ответа.
   4.3. Вернуть ответ с цитированием источников.
5. Если намерение — подготовка перевода (сценарий B):
   5.1. Извлечь получателя, сумму, валюту, счёт списания из сущностей.
   5.2. При отсутствии реквизитов — запросить уточнение у клиента.
   5.3. Создать действие PREPARE_TRANSFER с ключом идемпотентности.
   5.4. Вернуть карточку операции для подтверждения клиентом.
6. Если намерение — регистрация спора (сценарий C):
   6.1. Получить операции клиента из Core Banking API.
   6.2. Создать действие REGISTER_DISPUTE.
   6.3. Вернуть номер обращения с предупреждением, что это не гарантия возврата.
7. Если намерение — эскалация к сотруднику:
   7.1. Создать действие ESCALATE_TO_HUMAN с контекстом диалога.
   7.2. Передать контекст в систему поддержки.
8. Записать все действия в аудит-лог.

# Входные атрибуты

| Атрибут | Где передается | Тип данных | Описание |
|---------|---------------|------------|----------|
| client_id | body | string | Идентификатор клиента |
| message | body | string | Текст сообщения клиента на русском языке |
| context | body | object | Дополнительный контекст (опционально) |
| context.as_of | body | string (date-time) | Дата, на которую запрашивается информация (для исторических тарифов) |

# Выходные атрибуты

| Атрибут | Тип данных | Описание |
|---------|------------|----------|
| scenario | string | Сценарий обработки (A, B, C, escalation, unknown) |
| status | string | Статус обработки (ok, prepared, registered, escalated, no_data, cancelled, executed, failed) |
| message | string | Ответ клиенту на русском языке |
| action_id | string | Идентификатор действия (если создано) |
| idempotency_key | string | Ключ идемпотентности (если применимо) |
| sources | array[string] | Источники знаний, использованные для формирования ответа |
| confidence | number | Уверенность модели в ответе (0.0–1.0) |
| requires_confirmation | boolean | Требуется ли подтверждение клиентом |
| requires_human_review | boolean | Требуется ли проверка человеком |

# Пример запроса

```json
{
  "client_id": "client-12345",
  "message": "Почему в этом месяце списали 299 рублей за обслуживание карты?",
  "context": {
    "as_of": "2024-06-15T00:00:00Z"
  }
}
```

# Пример ответа

Успешный ответ (сценарий A — объяснение комиссии):

```json
{
  "scenario": "A",
  "status": "ok",
  "message": "Ежемесячная комиссия за обслуживание карты «Классическая» — 299 рублей. По вашему индивидуальному договору могут действовать особые условия.",
  "sources": [
    "Тариф «Классическая карта» (v2.1, с 01.01.2024): internal://docs/tariffs/card-classic-v2.1",
    "Индивидуальные условия договора клиента 12345 (v1.0, с 01.03.2024): internal://docs/contracts/client-12345"
  ],
  "confidence": 0.92,
  "requires_confirmation": false,
  "requires_human_review": false
}
```

Ошибка — не найдены данные по тарифам:

```json
{
  "scenario": "A",
  "status": "no_data",
  "message": "Не удалось найти информацию о тарифах и условиях, действовавших на указанную дату. Обратитесь в поддержку.",
  "sources": [],
  "confidence": 0.0,
  "requires_confirmation": false,
  "requires_human_review": false
}
```

# Коды ответа

- `200` — успешный ответ от ассистента
- `400` — некорректный запрос (отсутствуют обязательные поля)
- `401` — не авторизован (отсутствует или неверен JWT токен)
- `500` — внутренняя ошибка сервера (ошибка LLM или RAG сервиса)
