# ADR-0001: Общая архитектура AI-ассистента банка

## Статус
Принято

## Контекст
Банку нужен персональный AI-ассистент для розничных клиентов, который может отвечать на вопросы о финансах, готовить переводы и инициировать сервисные процессы. Критически важно: ошибки AI не должны приводить к несанкционированным операциям, раскрытию данных или недостоверным обещаниям.

## Рассмотренные альтернативы

### Вариант A: Полностью автономный AI-агент
AI модель сама принимает решения и выполняет операции через API банка.

**Плюсы:** Максимально бесшовный пользовательский опыт.
**Минусы:** Высокий риск несанкционированных операций, галлюцинации могут привести к потере денег клиента, сложно аудитировать.

### Вариант B: Гибридный (подготовка + подтверждение клиентом) — ВЫБРАН
AI подготавливает операцию и показывает параметры клиенту, клиент подтверждает через 2FA, затем операция исполняется банковской системой.

**Плюсы:** Клиент всегда контролирует движение денег, модель не может autonomously списать средства, простое аудитирование.
**Минусы:** Ещё один шаг для клиента (подтверждение), ligeramente ниже конверсия.

### Вариант C: Только консультативный (без действий)
AI только отвечает на вопросы, все операции — через обычное меню приложения.

**Плюсы:** Нулевой риск финансовых потерь через AI.
**Минусы:** Не закрывает бизнес-требование «помогать выполнять операции».

## Решение
Принят **Вариант B** — гибридная архитектура:
- AI понимает запрос, извлекает параметры, готовит операцию
- Клиент явно подтверждает каждое действие с деньгами (2FA / push)
- Все действия логируются в аудит
- Основные функции приложения работают независимо от ассистента

## Последствия
- Необходима интеграция с системой 2FA/подтверждения банка
- Требуется механизм идемпотентности для предотвращения дублей операций
- Увеличение времени на выполнение операции (дополнительный шаг подтверждения)
- Необходимо обучение клиентов новому интерфейсу подтверждения
