# ADR-0003: Механизм подтверждения действий клиентом (2FA)

## Статус
Принято

## Контекст
Все действия, приводящие к движению денег (переводы, платежи), требуют явного подтверждения клиента. Модель AI не может самостоятельно подтверждать или исполнять такие операции.

## Рассмотренные альтернативы

### Вариант A: Подтверждение в чате (текст «да/нет»)
Клиент отвечает текстом в чате, чтобы подтвердить операцию.

**Плюсы:** Просто, не требует дополнительных интеграций.
**Минусы:** Низкий уровень безопасности, возможно случайное подтверждение, не соответствует банковским стандартам 2FA.

### Вариант B: Push-уведомление + 2FA в приложении — ВЫБРАН
Операция préparée AI, клиент получает push-уведомление в приложении банка с деталями операции, подтверждает через биометрию/PIN.

**Плюсы:** Соответствие банковским стандартам безопасности, клиент видит полные детали, сложно подтвердить случайно.
**Минусы:** Требуется интеграция с системой push-уведомлений и 2FA банка, дополнительный шаг для клиента.

### Вариант C: SMS-код подтверждения
Код приходит по SMS.

**Плюсы:** Стандартный подход банков.
**Минусы:** SIM-swap атаки, задержки доставки, дополнительная стоимость SMS.

## Решение
Принят **Вариант B** — push-уведомление с 2FA в мобильном приложении банка:
- AI готовит операцию и показывает параметры клиенту в чате
- Клиент подтверждает через push-уведомление с биометрией/PIN
- Операция исполняется только после успешного подтверждения
- Изменение суммы или реквизитов требует нового подтверждения

## Последствия
- Необходима интеграция с существующей системой 2FA банка
- Время выполнения операции увеличивается из-за шага подтверждения
- Клиент должен установить мобильное приложение с push-уведомлениями
