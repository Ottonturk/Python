# ADR-0002: RAG-база знаний с версионированием условий

## Статус
Принято

## Контекст
Ассистент должен отвечать на вопросы о продуктах, тарифах и условиях обслуживания с учётом индивидуальных условий клиента и исторических версий документов. Рекламное описание может не совпадать с договором, условия могут меняться со временем.

## Рассмотренные альтернативы

### Вариант A: Простой поиск по документам без версий
Поиск по тексту документов без учёта даты действия и версии.

**Плюсы:** Простая реализация.
**Минусы:** Невозможно отличить актуальный тариф от архивного, нельзя объяснить списание по старым условиям, риск неверного ответа.

### Вариант B: RAG с версионированием чанков — ВЫБРАН
Каждый чанк документа хранит метаданные: `document_id`, `version`, `effective_from`, `effective_to`, `source_url`. Поиск фильтрует по актуальности на дату события (например, дату списания).

**Плюсы:** Точные ответы с учётом исторических условий, возможность ссылаться на конкретный пункт договора, поддержка индивидуальных условий клиента.
**Минусы:** Сложнее индексация, необходимо хранение версий документов, необходимо разрешение противоречий между версиями.

## Решение
Принят **Вариант B**:
- RAG-пайплайн с разбиением документов на чанки и метаданными версий
- При ответе на вопрос о прошлом списании используется версия условий, действовавшая на дату списания
- Приоритет источников: индивидуальный договор > тариф > FAQ > рекламное описание
- Каждый ответ содержит ссылку на источник (확омментирование)

## Последствия
- Необходим процесс обновления индекса при публикации новых версий документов
- Ответственность за актуальность базы знаний лежит на producto-менеджменте и юридическом отделе
- Необходимо разрешение противоречий между версиями документов
