Публикуй только артефакты, прошедшие ревью субагентом `review-docs`
(вердикт `APPROVED`), если явно не указано иное. Запусти его через Agent
(subagent_type: `review-docs`) перед публикацией, если ревью ещё не
проводилось в текущей сессии.

## Проверка подключения

Перед публикацией убедись, что MCP-сервер подключен: `claude mcp list`
должен показать `wiki-oauth ✔ Connected`. Если не подключен — не пытаться
чинить конфиг самостоятельно, сообщить пользователю: нужно
`source .claude/wiki.local.env` в том терминале, где запущен `claude`, и
перезапуск сессии (конфиг MCP читается только при (пере)старте).

## Структура раздела

Корень — `homepage/ii-dokumentaciya` ("ИИ документация"). Эта страница уже
существует, **никогда не пересоздавай её**. Перед публикацией проверь
`GetPageTree` по этому slug, чтобы увидеть уже существующие подразделы и не
создать дубликат по тому же slug.

Новый материал по одному ТЗ — это один подраздел
`homepage/ii-dokumentaciya/<slug>`, где `<slug>` — имя файла ТЗ без
расширения (например, `order-lifecycle`, `book-loan`).

### Если ТЗ описывает один метод

```
homepage/ii-dokumentaciya/<slug>              — обзорная страница
homepage/ii-dokumentaciya/<slug>/erd
homepage/ii-dokumentaciya/<slug>/sequence
homepage/ii-dokumentaciya/<slug>/swagger
homepage/ii-dokumentaciya/<slug>/method        — описание метода
```

### Если ТЗ описывает несколько методов

```
homepage/ii-dokumentaciya/<slug>                            — обзорная страница
homepage/ii-dokumentaciya/<slug>/erd                        — общая ERD на все сущности ТЗ
homepage/ii-dokumentaciya/<slug>/swagger                    — общий swagger на все методы ТЗ
homepage/ii-dokumentaciya/<slug>/<метод-1-slug>              — описание метода 1
homepage/ii-dokumentaciya/<slug>/<метод-1-slug>/sequence     — его sequence-диаграмма
homepage/ii-dokumentaciya/<slug>/<метод-2-slug>              — описание метода 2
homepage/ii-dokumentaciya/<slug>/<метод-2-slug>/sequence
... (по одному блоку метод+sequence на каждый метод)
```

Slug метода — тот же, что и имя файла артефакта в `artifacts/methods/`.

## Порядок создания страниц (критично)

`CreatePage` требует, чтобы **непосредственный родитель уже существовал** —
иначе `400 NO_PARENT_PAGE`. Всегда создавай сверху вниз:

1. Обзорная страница `<slug>`.
2. Её прямые дети: `erd`, `swagger`, и для каждого метода — страница метода
   (`<slug>/<метод>` либо `<slug>/method`, если метод один).
3. Только после этого — `sequence` как ребёнок уже созданной страницы
   метода.

`CreatePage` принимает только `slug` + `title` (+ `content`) — родитель
определяется по префиксу slug, отдельного поля для него нет.

## Как оформлять контент

- **ERD и Sequence** (`.puml`): заголовок `##`, затем код диаграммы в
  фенсе ```` ```plantuml ... ``` ````, без изменений содержимого файла.
- **Swagger** (`.yaml`): заголовок `##`, затем код в фенсе
  ```` ```yaml ... ``` ````, без изменений содержимого файла.
- **Описание метода** (`.md` из `artifacts/methods/`): вставляй markdown
  как есть — заголовки `##`/`###` дают то же оглавление. В разделе
  "Оглавление" якоря должны буквально совпадать с текстом заголовков
  (пробел → дефис, регистр как в заголовке), например
  `[Назначение](#Назначение)`. Если у метода есть отдельная страница
  `sequence`, добавь последним пунктом оглавления ссылку на неё:
  `[Sequence-диаграмма](sequence)`.
- **Обзорная страница** подраздела: `##`-заголовок с названием, 1–2
  предложения о том, что делает ТЗ (из его вводного абзаца), раздел
  `### Сущности` — список сущностей и их атрибутов из ТЗ, раздел
  `### Артефакты` — относительные ссылки на все дочерние страницы
  (`[ERD](erd)`, `[Swagger (OpenAPI)](swagger)`, `[Метод: ...](<slug>)`).

Ссылки между страницами подраздела — всегда относительные, без ведущего
слеша (`erd`, `swagger`, `order-checkout`, `sequence`), а не полный slug.

## После публикации

Публикация страницы подтверждается наличием `id` в ответе `CreatePage` —
дополнительно открывать/проверять созданные страницы не нужно. По итогу
кратко перечисли пользователю, какие slug'и появились и под каким
родительским разделом.
