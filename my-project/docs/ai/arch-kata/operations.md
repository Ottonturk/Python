# 7. Эксплуатационная модель

## 7.1 Мониторинг

| Метрика | Источник | Порог алерта | Ответственный |
|---------|----------|--------------|---------------|
| Доступность чата API | Prometheus + Grafana | < 99.5% за 5 мин | Дежурный инженеринг |
| Время ответа LLM | Prometheus | > 5 сек (p95) | ML-инженеринг |
| Доля несанкционированных операций | Audit log | > 0 | Security officer |
| Ошибки интеграции с Core Banking | ELK | > 1% запросов | Бэкенд-команда |
| CSAT после диалога | Опрос клиента | < 3.0 | Produkt-менеджмент |

## 7.2 Аудит

- Все действия AI логируются в immutable хранилище (WORM)
- Хранение аудит-логов: не менее 5 лет
- Ежемесячный аудит выборки диалогов (не менее 100 диалогов)
- Доступ к аудиту: только роли `security-auditor`, `compliance-officer`

## 7.3 Деградация (Graceful Degradation)

| Szenario | Поведение системы |
|----------|------------------|
| LLM недоступен | Чат отключён, клиенту сообщение: «Ассистент временно недоступен, используйте обычное меню приложения» |
| Core Banking недоступен | Основные функции приложения работают, ассистент сообщает: «Не удалось получить данные о счетах, попробуйте позже» |
| RAG/база знаний недоступна | Ассистент отвечает только на основе кэшированных данных, для остального — передача сотруднику |
| Сбой 2FA/подтверждения | Операция приостанавливается, клиенту уведомление о необходимости повторной авторизации |

## 7.4 Реагирование на инциденты

| Уровень | Пример | Время реакции | Кто реагирует |
|---------|--------|--------------|---------------|
| Критический (P1) | Несанкционированная операция, утечка данных | 15 мин | Дежурный инженеринг + Security |
| Высокий (P2) | LLM не отвечает, ошибки переводов | 1 час | ML-инженеринг, Бэкенд |
| Средний (P3) | Ухудшение качества ответов, медленная работа | 4 часа | ML-инженеринг |
| Низкий (P4) | Опечатки в ответах, мелкие баги UI | Следующий спринт | Команда разработки |

## 7.5 Передача сотруднику (Escalation)

- Клиент может запросить оператора в любой момент
- При передаче сотруднику передаётся: полная история диалога, контекст (карты, операции, текущее действие), номер обращения (если есть)
- Сотрудник видит, какие действия AI уже準овил, а какие требуют подтверждения
- После завершения диалога с оператором сессия ассистента возобновляется с контекстом

## 7.6 SLA пилота

- Доступность ассистента: 99.5% (вне плановых работ)
- Время ответа на текстовый запрос: p95 < 5 секунд
- Время инициации обращения в поддержку: < 30 секунд
- Время решения инцидента P1: < 4 часа
