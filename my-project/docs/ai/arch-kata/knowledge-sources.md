# 4. Подход к источникам знаний

## 4.1 Источники знаний

| Источник | Тип данных | Частота обновления | Ответственный |
|----------|------------|-------------------|---------------|
| Каталог продуктов банка | Тарифы, условия, описания | При изменении тарифов | Produkt-менеджмент |
| Договоры клиентов | Индивидуальные условия | При заключении/изменении договора | Юридический отдел |
| FAQ банка | Ответы на типовые вопросы | Ежемесячно | Служба поддержки |
| Инструкции по операциям | Пошаговые алгоритмы | При изменении процедур | Операционный отдел |
| История операций клиента | Транзакции, списания, переводы | В реальном времени | Онлайн-банкинг (Core) |

## 4.2 RAG-пайплайн

```
[Документы банка] → [Chunking] → [Embedding] → [Vector DB] → [Поиск по запросу] → [LLM] → [Ответ с цитированием источника]
```

### Этапы:
1. **Загрузка и парсинг** — PDF, HTML, DOC с условиями продуктов, тарифами, FAQ
2. **Разбиение на чанки** — по разделам договора/тарифа с сохранением метаданных (версия, дата действия, источник)
3. **Векторизация** — эмбеддинги на русскоязычной модели
4. **Хранение** — Vector DB с метаданными: `document_id`, `version`, `effective_from`, `effective_to`, `source_url`
5. **Поиск** — гибридный (векторный + ключевые слова) с фильтром по актуальности на дату запроса
6. **Генерация** — LLM получает только релевантные чанки с метаданными, обязан ссылаться на источник

## 4.3 Актуальность и исторические версии

- Каждый чанк хранит `effective_from` и `effective_to` — период действия условия
- При ответе на вопрос о списке в прошлом используется версия условий, действовавшая на дату списания
- При изменении тарифа старые версии не удаляются, а помечаются архивными
- Индекс перестраивается при публикации новой версии документа

## 4.4 Разрешение противоречий

| Ситуация | Приоритет источника |
|----------|-------------------|
| Индивидуальный договор клиента vs рекламное описание | Договор клиента (индивидуальные условия превосходят стандартные) |
| Актуальный тариф vs архивная версия | Актуальная версия для новых операций, архивная — для объяснения прошлых списаний |
| FAQ vs документ тарифов | Документ тарифов (юридически значимый) |
| Противоречие между версиями одного документа | Новая версия отменяет старую, если не указано иное |

## 4.5 Подтверждение ответа (Grounding)

- Каждый ответ AI должен содержать ссылку на источник: раздел договора, пункт тарифа, статью FAQ
- Если источник не найден или противоречив — ассистент сообщает: «Не могу точно ответить, уточните, пожалуйста, или обратитесь в поддержку»
- Запрещено придумывать причины списания или обещать возврат без подтверждения из системы
- Уровень достоверности помечается в метаданных ответа: `confirmed_by_source`, `partially_confirmed`, `not_confirmed`
