# 1. Границы решения и состав пилота

## Границы решения

### В зоне ответственности (In Scope)

**Мобильное приложение и интернет-банк:**
- Чат-интерфейс с AI-ассистентом
- Отображение ответов, предложений по операциям, карточек подтверждения
- Интеграция с существующим онлайн-банкингом через API

**AI-ассистент (серверная часть):**
- Понимание естественного языка (NLU) на русском языке
- Поиск и генерация ответов из базы знаний банка (RAG)
- Подготовка банковских операций (переводы, платежи, обращения)
- Оркестрация подтверждения клиентом (2FA, push-уведомления)
- Передача диалога сотруднику поддержки с контекстом
- Логирование, аудит, мониторинг

### Вне зоны ответственности (Out of Scope)

- Самостоятельное выполнение операций без подтверждения клиента
- Выдача кредитов, открытие вкладов, изменение тарифов
- Голосовой интерфейс (только текстовый чат в MVP)
- Интеграция с внешними платёжными системами (только внутренние переводы банка)
- Мультивалютные счета вне базового пакета услуг

## Состав пилота (MVP release)

| Компонент | Статус в пилоте | Обоснование приоритета |
|-----------|----------------|------------------------|
| Чат-интерфейс в мобильном приложении | ✅ Включен | Основной канал взаимодействия с клиентом |
| NLU + LLM (облачный или on-premise) | ✅ Включен | Ядро ассистента, понимание запросов |
| База знаний банка (products, tariffs, FAQ) | ✅ Включен | Необходима для ответов на вопросы |
| Интеграция с онлайн-банкингом (счета, карты, операции) | ✅ Включен | Нужна для контекста клиента и подготовки операций |
| Сценарий А: Объяснение комиссии | ✅ Включен | Обязательный scénario из ТЗ |
| Сценарий Б: Перевод по разговорному запросу | ✅ Включен | Обязательный scénario из ТЗ |
| Сценарий В: Спорная операция (инициирование обращения) | ✅ Включен | Обязательныйénario из ТЗ |
| Передача диалога сотруднику с контекстом | ✅ Включен | Требование ТЗ для сложных ситуаций |
| Идемпотентность операций | ✅ Включен | Требование безопасности (no double-charge) |
| Аудит и логирование всех действий AI | ✅ Включен | Требование безопасности и соответствия |
| Мониторинг и алерты | ✅ Включен | Эксплуатационная модель |
| E2E тестовые наборы для AI | ✅ Включен | Подход к оценке качества |
| Голосовой интерфейс | ❌ Исключён | Не входит в первый релиз |
| Открытие новых продуктов через ассистента | ❌ Исключён | Слишком высокий риск для пилота |
| Автоматическое принятие решений о возврате | ❌ Исключён | Требуется человек, чтобы избежать ошибок AI |

## Обоснование приоритетов

1. **Безопасность превыше всего:** все действия, приводящие к движению денег, требуют явного подтверждения клиента. Модель не может autonomously подтверждать переводы.
2. **Ценность для клиента:** сценарии А, Б, В закрывают наиболее частые запросы в поддержку (комиссии, переводы, споры).
3. **Снижение риска:** исключение автоматических решений о возвратах и открытии продуктов снижает риск несанкционированных операций.
4. **Зависимость от основного приложения:** основные функции банка работают независимо от доступности ассистента (graceful degradation).
