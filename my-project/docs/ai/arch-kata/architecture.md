# 2. Архитектурные схемы

## 2.1 Контекстная диаграмма (C4 Level 1)

```
+---------------------+      HTTP/JSON + JWT      +---------------------------+
|   Клиент (физ. лицо)| <----------------------> |  Банковское приложение    |
|   (моб. приложение /|      или WebSocket        |  и интернет-банк (UI)   |
|   интернет-банк)    |                          +---------------------------+
+---------------------+                                         |
                                                                | internal API
                                                                v
+---------------------+      gRPC / REST      +---------------------------+
|   AI-ассистент      | <---------------------> |  Онлайн-банкинг (Core)  |
|   (Chat API Service)|      (счета, карты,     |  API: баланс, операции,  |
|   - NLU/LLM         |      платежи, обращения)|      реквизиты          |
|   - RAG             |      + webhooks         +---------------------------+
|   - Action Manager  |                                         |
+---------------------+                                         |
                                                                | REST + OAuth2
                                                                v
+---------------------+      RAG / Search       +---------------------------+
|   База знаний       | <---------------------> |  Source of Truth (Docs)   |
|   (Vector DB +      |      (реиндексация)     |  - Продукты, тарифы, FAQ  |
|   поиск сервис)     |      + versioning       |  - Условия договоров      |
+---------------------+      + synonyms          +---------------------------+
                                   |
                                   | audit logs
                                   v
                          +----------------------+
                          |  Audit & Monitoring  |
                          |  (ELK / Prometheus)  |
                          +----------------------+

Границы доверия:
- ✅ Доверенная зона: онлайн-банкинг Core API (внутренняя сеть банка, mTLS)
- ⚠️  Полу-доверие: AI-ассистент (обрабатывает персональные данные, шифрование на стороне клиента)
- ❌ Недоверенная зона: клиентское устройство (моб. приложение, браузер)
- ❌ Внешняя зона: сторонние LLM-провайдеры (если используется облачная модель — только деидентифицированные данные)
```

## 2.2 Компонентная диаграмма (C4 Level 2)

### AI-ассистент — внутренние компоненты

| Компонент | Ответственность |
|-----------|----------------|
| Chat API (REST/gRPC) | Точка входа, аутентификация клиента, проксирование запросов |
| NLU / LLM | Понимание намерений, извлечение сущностей, генерация ответов |
| RAG Service | Поиск ответов из базы знаний банка с учётом версий |
| Action Manager | Подготовка операций, идемпотентность, координация с Core |
| Context Store | История сессий, профиль клиента, контекст диалога |
| Escalation | Передача диалога сотруднику поддержки с контекстом |
| AuthZ / Permissions | Проверка прав доступа к счетам и операциям клиента |
| Audit Log | Неизменяемый журнал всех действий AI |
| Evaluator | Оценка качества ответов AI, негативные проверки |

### Границы доверия между компонентами

| От | К | Механизм доверия | Защита |
|----|---|-----------------|--------|
| Клиент | Chat API | JWT + mTLS | Требуется аутентификация клиента |
| Chat API | NLU/LLM | Токен сервиса | Только деидентифицированные данные |
| Chat API | Core Banking API | mTLS + OAuth2 | Права доступа клиента (scope) |
| Chat API | RAG Service | Внутренний сервис | Фильтр по правам клиента |
| Action Manager | Core Banking | mTLS + ключ идемпотентности | Повторные запросы не дублируют операцию |
| Escalation | Support System | API с контекстом диалога | Передача только согласованных данных |
