# 5. Механизм управления действиями

## 5.1 Принципы

1. **Никаких автоматических операций с деньгами без подтверждения клиента** — модель только готовит операцию, клиент подтверждает
2. **Явная авторизация** — каждое действие требует проверки прав клиента на счёт/карту
3. **Предварительные проверки** — баланс, лимиты, blocked status, подозрительная активность перед準 execution
4. **Идемпотентность** — повторный запрос с тем же ключом не приводит к дублированию операции
5. **Восстановление после сбоя** — откат или завершение прерванной операции

## 5.2 Жизненный цикл действия

```
Подготовка → Проверка прав → Проверка лимитов/баланса → Карточка для подтверждения → 
Подтверждение клиентом (2FA) → Исполнение → Подтверждение результата → Аудит
```

## 5.3 Идемпотентность

- Каждая операция получает `idempotency_key = hash(client_id + action_type + параметры + timestamp_округлённый)`
- При повторном запросе с тем же ключом возвращается результат первой операции
- Ключ действителен в течение 24 часов
- Изменение суммы или реквизитов = новый ключ = nuova операция с новым подтверждением

## 5.4 Таблица действий и требуемых подтверждений

| Действие | Требует подтверждения клиентом | 2FA | Идемпотентность | Откат |
|----------|-------------------------------|-----|-----------------|-------|
| Объяснение комиссии | ❌ Нет | ❌ Нет | ❌ Нет | ❌ Нет |
| Подготовка перевода | ✅ Да (показать параметры) | ✅ Да | ✅ Да | ✅ Да |
| Исполнение перевода | ✅ Да (уже подтверждено) | ✅ Да | ✅ Да | ⚠️ Частично (отмена до списания) |
| Регистрация спора | ❌ Нет | ❌ Нет | ✅ Да | ❌ Нет |
| Передача сотруднику | ❌ Нет | ❌ Нет | ❌ Нет | ❌ Нет |

## 5.5 Восстановление после сбоя

| Сбой | Действие |
|------|----------|
| Тайм-аут при подтверждении клиентом | Операция переходит в статус `PENDING_CONFIRMATION`, истекает через 30 мин, клиенту отправляется напоминание |
| Ошибка Core Banking при исполнении | Операция в статусе `FAILED`, клиенту уведомление, средства не списаны, повтор 가능 с новым подтверждением |
| Сбой связи между AI и Core | Операция в статусе `UNKNOWN`, проверка через вебхук Core, ручное разрешение оператором |
| Повторный запрос после тайм-аута | Проверка по идемпотентному ключу, если операция уже executеd — возвращаем результат без дублирования |

## 5.6 Аудит всех действий AI

Каждое действие записывается в immutable audit log:
- `action_id`, `client_id`, `timestamp`, `action_type`, `parameters`, `idempotency_key`, `client_confirmation`, `result`, `error_code`, `source_system`

Аудит хранится не менее 5 лет, доступ только для уполномоченных сотрудников безопасности и аудита.
